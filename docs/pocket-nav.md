# 掌机导航：点开整张地区图，画红线，走过去

> 面向维护者。做的是什么、数据从哪来、哪一步会失败、失败了会怎样，都写在这里。
> 回归：`node tools/verify-nav.mjs`（21 条）、`node tools/verify-nav-id.mjs`（15 条）。

## 一、能做什么

| 动作 | 结果 |
| --- | --- |
| 点左上角小地图 | 铺开成整张地区图（不是走过的素描，是卡带里的原始地图） |
| 点图上任意一格 | 定目的地，画红线；点不动的地方会吸附到最近能站的格子 |
| 从「去哪儿…」挑 | 城镇 / 森林 / 洞窟，跨图也会连着算 |
| 缩回小窗 | 红线留着，只画接下来 10 步 + 一个箭头 |
| 「走过去」 | 脚本代按方向键沿路走；再点一次随时停 |

红线**只走两条腿能走的路**：水面、单向坎、跳崖、四面不可通一律当墙，宁可绕路也不出「跳一下」「游过去」这种动作。

## 二、数据从卡带里现读，不进仓库

启动后第一次打开导航时解析一遍（约 0.3 秒，518 张图），之后全部走缓存。

| 要什么 | 在哪 | 怎么读 |
| --- | --- | --- |
| 地图清单 | ROM 里一条扁平的地图头指针数组 | 先找「一长串都指向卡带里的字」，再逐条验 `MapHeader`（0x1C 字节）；数组可能被后面别的指针污染，用「相邻图是否互指」滑窗定界 |
| 尺寸与地图块 | `MapLayout` | `s32 w, s32 h, u16* border, u16* map, Tileset* 主, Tileset* 副` |
| 能不能走 | 每格 u16 | bit0-9 元瓦片号、**bit10-11 碰撞位**（非 0 = 走不过去）、bit12-15 高度 |
| 是什么地形 | 元瓦片属性表 | `Tileset + 0x10` 指向 `u16[1024]`，低 8 位是地形行为（`MB_*`） |
| 门通向哪 | `MapEvents` | `u8 物体数, u8 传送数, ...`，传送点 8 字节：`s16 x, s16 y, u8 高度, u8 门号, u8 序, u8 组` |
| 走到边上通哪 | `MapConnections` | `s32 条数, 指针`；每条 12 字节：`u8 方向, s32 偏移, u8 组, u8 序` |

**地图编号（组,序）怎么对上**：ROM 里数组的顺序就是组的顺序，官方 518 张。我们用反编译工程的 `map_groups.json` 逐张核对过尺寸，**518/518 完全一致**——所以 `(组,序) → 扁平下标` 是可信的。组内张数写死在 `MOON_MAP_GROUP_COUNTS`；张数对不上（改版）时 `countsOk = false`，跨图导航自动降级，只保留本图内导航。

## 三、地形 → 代价

`MOON_BEHAVIOR_COST[行为]`，0 表示走不过去：

| 地形 | 代价 | 说明 |
| --- | --- | --- |
| 普通地面 / 室内地板 / 洞窟 / 冰面 | 1 | 走 |
| 矮草、沙地 | 2 | 能走，但会遇敌，绕得开就绕 |
| 高草、长草、火山灰草 | 3 | 更不想走 |
| 水面（池塘 / 深水 / 海 / 浅滩 / 水洼） | 0 | 没冲浪就是墙 |
| 单向坎、跳崖、四面不可通（`MB_IMPASSABLE_*` / `MB_JUMP_*`） | 0 | 要「跳一下」，算交互，不算走路 |

A* 用四方向 + 曼哈顿启发，代价就是踩上去的数。所以「最短」在这套权重下等价于「最少折腾」。

## 四、跨图：先选骨架，再走实路

1. `moonMapGraph()` 把每张图的传送点与边界连接变成有向边（门 8 分、边界 2 分）。
2. `moonRouteMaps()` 在这个小图上跑 Dijkstra，得到「走哪几道门」。
3. `moonPlan()` 逐段用 A* 走到门前；走边界时**整条边扫一遍**找一个能站的格子（边界那一行多半是树）。
4. 进下一张图的落点：走边界从对侧进（按 `offset` 平移），走门找「指回上一张图、门号相同」的那扇门，找不到就就近吸附。

实测：未白镇 → 橙华市 = 未白镇 → 101 号路 → 古辰镇 → 102 号路 → 橙华市，156 步，5 段。
主线连通片 319 张图，16 个关键地点里 15 个在片内（琉璃市要潜水，单独算）。

## 五、认图：知道自己站在哪

核心只导出 4 个内存符号（ROM / 存档 / 帧缓冲 / 金手指文本），**没有 RAM 出口**，所以坐标只能看画面：

1. 把当前帧按 16px 切成 **15×8** 块（只取上面 128px，底部是改版常驻 HUD），每块取平均亮度；
2. 每张地图也做成「一格一个亮度」的网格（元瓦片平均亮度，按瓦片集缓存）；
3. 逐图逐格比对，命中的格数就是得分；玩家在窗口第 (7,5) 格。

**两条硬规矩，宁可不说，不许说错**：

- 这一窗几乎是纯色（标准差 < 9）→ 返回空。树林、墙面、水面在几百张图里长得一样，谁也对不准。
- 第一名和第二名差不到 2 格 → 返回空。这就是「地形有歧义」。

实测抽样 82 张：敢答 11 张，**答错 0 张**；加噪声（模拟 NPC / 天气）后仍答错 0 张。代价是认不出的时候偏多，界面会写「这一帧认不出来，走两步再点」。

## 六、一键走过去

`navWalkSegment()` 把一段路按「同方向连续几步」合成一次长按（每步约 170ms），按住 → 松开 → 用 `MOON_POCKET.map.state()` 的位置差确认真的动了：

- 明显没动（连续 2 格以上原地）→ 停，提示「被挡住了」；
- 遇敌 / 进菜单导致画面变了 → 同上，停；
- 走到边界 / 门 → 等 1.4 秒让地图加载，重新认一次位置，接着走下一段。

按键走 `core.input(name, down)`，只动 `coreKeys`，不碰游戏数据。

## 七、已知边界

1. **认不出就导不了**：战斗、对话、菜单、纯色地形都不认。没有内存出口之前，这是硬限制。
2. **改版可能降级**：地图张数与官方不一致时（`countsOk=false`），跨图导航关闭，只剩本图内导航。
3. **要秘传技的地方不导**：冲浪、潜水、推石、爬瀑布都不算「走路」，路线会直接说走不过去。
4. **单向通行没建模**：坎、跳崖当墙，所以「跳下去抄近路」这种走法不会出现在路线里。
5. **NPC 会挡路**：路线不知道谁会站那，撞上就停，停下来自己绕。
