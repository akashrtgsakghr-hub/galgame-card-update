# 副本系统（主神空间 · 无限流）设计稿

> 状态：**设计稿，未实现**。五个关键决策已于 2026-11-24 全部定稿（见 §10），可以直接开工。
> 目标：让玩家和「心爱的 Ta」被主神空间选中，进副本打本，再回主线继续谈恋爱——两边随时来回，记忆可选互通。
> 配套：`docs/dungeon-seed.md`（母题库 + 8 个可直接抄进世界书的成品副本）。

---

## 0. 素材从哪来（已定稿）

**不抓笔趣阁。** 理由和商不商用无关：「免费阅读」≠「作者授权」，笔趣阁上的正文本身就是盗版副本。
这张卡最终要挂 GitHub 公开分发，「不商用」不能免掉「复制 + 改编 + 向公众提供」这三件事。

替代来源按风险分三档，**只用 A 档，B 档只借体裁不搬文本，C 档不碰**：

| 档 | 来源 | 能不能用 | 代价 |
| --- | --- | --- | --- |
| **A** | 志怪古籍：聊斋志异、子不语、阅微草堂笔记、酉阳杂俎、夷坚志、太平广记、搜神记 | ✅ 随便用、随便改、**不用署名** | 无（作者逝世数百年，作品在公共领域） |
| **B** | SCP 基金会中/英分部、Creepypasta Wiki | ⚠️ 可商用，但 CC BY-SA 3.0 **有传染性** | 强制署名 + 衍生作品必须同样以 CC BY-SA 发布，整张卡的副本部分都得跟着开源 |
| C | 笔趣阁 / 番茄 / 七猫 / 各类网文站 | ❌ | 未授权正文，属侵权 |

**为什么 A 档够用**：规则怪谈这个类型靠**母题**活着——「夜行莫回头」「庙里别数神像」「听见叫名字别应」
这类规则是全类型共享的公共素材。而中国古代志怪里全是这些母题的原始版本，比现代网文更野。
按「思想/表达二分法」，母题和规则格式（一二三条）不受版权保护，受保护的是具体遣词造句——
所以**取母题、自己重写正文**是干净的。

**B 档怎么用**：只借「异常编号 + 收容档案 + 实验记录」这个**体裁结构**（体裁属形式，不受保护），
条目的正文、代号、编号、专有名词全部自己重写，一个字都不搬。这样就不触发 CC BY-SA 传染。

具体的母题库和可直接抄用的副本条目，见 `docs/dungeon-seed.md`。

## 1. 它是什么

一句话：**主神空间是「中继站」，副本是「关卡」，积分是「钱」。**

| 元素 | 在本卡里的形态 |
| --- | --- |
| 主神空间 | 一个面板页（休整 / 兑换 / 选本），不是新地图 |
| 副本 | **另开一个聊天**，里面是一次完整的生存解谜 |
| 积分 | 现有攻略模式的积分账本，副本里赚、空间里花 |
| 死亡 | 副本失败 → 扣积分 + 带一个「后遗症 buff」回主线，不真的删档 |
| 冷却 | 通关后 N 天不能再进本，期间只能兑换和谈恋爱 |

**和攻略模式的关系**：两个都是「模式」，**互斥**。开副本模式会自动关掉攻略模式（反之亦然），
因为两者都要改注入、都要动账本，同时开会互相踩。

## 2. 双对话架构（这是整个系统唯一的技术难点）

玩家要在**两个聊天**里来回：主线聊天（谈恋爱）和副本聊天（打本）。
酒馆的 chat 是隔离的，所以「记忆互通」不能靠聊天记录，得靠**跨聊天的全局存储**。

### 2.1 谁是主线、谁是副本

```js
// 每个聊天给自己盖个章（chatMetadata，随聊天走）
chatMetadata.moon_dungeon_role = 'main'   // 主线聊天
chatMetadata.moon_dungeon_role = 'run'    // 副本聊天
chatMetadata.moon_dungeon_runId = 'd_1732...'  // 副本实例 id
```

### 2.2 共享的东西放哪

放**扩展级存储**（`getStorage()`，跨 chat，按角色卡隔离——和现有道具池同一套 key 规则）：

```js
moon_dungeon::<卡名> = {
  on: true,
  points: 0,                 // 不再单独存；一本账，直接读写 state.affectionPoints（见 5.2）
  cooldownUntil: 0,          // 冷却截止时间戳
  currentRun: { id, dungeonId, chatId, startedAt, progress } | null,
  digests: {
    main:  { text, updatedAt },        // 主线最近发生了什么（副本侧要读）
    runs:  [ { runId, dungeonId, text, at } ]   // 副本发生了什么（主线侧要读）
  },
  sync: 'both' | 'run-reads-main' | 'none'      // 记忆互通三档
}
```

### 2.3 记忆怎么走

```
主线聊天 ──写 digest.main──▶ 全局存储 ──注入──▶ 副本聊天
副本聊天 ──写 digest.runs──▶ 全局存储 ──注入──▶ 主线聊天
```

| 档位 | 主线能看到副本记忆 | 副本能看到主线记忆 | 适合 |
| --- | --- | --- | --- |
| **both**（默认，已定稿） | ✅ | ✅ | 你要的「两边记忆不存在不互通」 |
| run-reads-main | ❌ | ✅ | 副本里记得她，回来却像做了个梦 |
| none | ❌ | ❌ | 两条线彻底隔开 |

**定稿：默认 `both`，由玩家在设置里自行改成 `none` 彻底隔开。** 切换入口放在主神空间面板上，
标一句「改了不会丢数据，只是以后不互相注入」。切到 `none` 时**不清空已有 digest**——
玩家改回来还能看见旧记忆，只是那段时间的不再更新。

**摘要在哪生成**：不要每轮都总结（烧 token）。只在三个时机生成：

1. 从主线**进本**时：把最近 20 轮压成 300 字，写进 `digest.main`；
2. 副本**通关/失败**时：把这一本压成 400 字，push 进 `digest.runs`（只留最近 3 本）；
3. 手动点「同步记忆」时。

生成用现有的后台小模型链路（`callOpeningModel` 那套），失败就退回「取最近 800 字原文截断」，不能因为摘要失败卡住流程。

**注入长什么样**（副本聊天侧）：

```
【你记得的事 · 来自主线】
她昨天说过「别一个人去那种地方」。你不确定这里算不算那种地方。
（以下为压缩记忆，不是本轮发生的事，不要当成刚发生的对白）
……
```

**关键一句必须写进去**：`这是记忆，不是现场。不要复述、不要当成刚发生的事。`——否则 AI 会把摘要当剧情演一遍。

## 3. 时间怎么算（已定稿：跟着时钟走，不冻结）

副本里过了三天，主线过了多久？**定稿走 B：同步，用同一套时钟。**

| 方案 | 规则 | 结论 |
| --- | --- | --- |
| A 冻结 | 进出副本时主线时间、日期一律不动 | 已废弃：存活倒计时没东西可挂，20 轮永远只走 3 小时 |
| **B 同步（已采用）** | 副本里每轮照常调 `advanceWorldClock`，AI 写过夜就跳一天 | 倒计时活着，玩家看得见自己在熬时间 |
| C 可配 | 默认 A，设置里能改 B | 不做，多写一套逻辑，收益不抵成本 |

**实现约束**：

1. 副本内时钟**照常推进**（`advanceWorldClock`），步长沿用主线的「每轮分钟数」（默认 10 分钟）；
2. 但**主线 `_回合` 不加**——`_回合` 是主线的计数，副本自己按回合记在 `run` 里；
3. 时钟走出来的分钟数喂给 `dungeonAddElapsed()`，存活倒计时就靠它；
4. 事件导演在副本期间**仍然挂起**（`evt = null`）——时间在走，但不推主线事件；
5. 主线角色的「距离主线天数」照常被时钟吃掉：副本里熬一夜，回主线真的少一天。

**每轮有保底**：`max(时钟分钟, 存活时长 ÷ 回合数)`。
不然一个「撑一夜」（480 分钟）的本，按 10 分钟一轮要聊 48 轮，玩家只会以为脚本坏了。

**冷却也是游戏时间**（`cooldownUntilGame`）：通关 7 天、失败 3 天，都要剧情时间走过去才解冻。
玩家关掉页面不会消耗冷却 —— 这也是「主神空间不等人」的另一面：它只认你世界里过去的时间。

## 4. 一次副本的完整流程

```
主线聊天
  └─ 面板「主神空间」→ 选本 → 点「进入」
       ├─ 生成 runId、写 state.currentRun
       ├─ 生成 digest.main（摘要主线）
       ├─ 创建/切换到一个新聊天，盖章 role='run'
       └─ 注入：副本设定 + 规则 + 主线记忆 + 通关条件

副本聊天（AI 当主神，玩家当轮回者）
  ├─ 每轮：脚本记 progress（回合数、规则违反次数、线索数）
  ├─ 违反规则 3 次 / 理智 0 / 超时 → 失败
  └─ 达成通关条件 → 结算
       ├─ 加分（按难度 + 隐藏任务）
       ├─ 掉落（道具进背包，直接复用现有道具库）
       ├─ 写 digest.runs
       ├─ 设置 cooldownUntil = now + N 天
       └─ 提示「回到主线」→ 一键切回主线聊天

主线聊天
  └─ 第一轮注入：你们回来了 + 副本记忆（按 sync 档位）+ 冷却剩余时间
```

**失败也要能回来**：失败不删档，扣分 + 给一个 24 小时的 debuff（现有 buff 系统直接能用），
并**缩短冷却**（比如 1 天而不是 3 天）——惩罚是「难受」，不是「劝退」。

## 5. 积分、冷却、兑换

### 5.1 冷却

| 结果 | 冷却（游戏时间） | 之后 |
| --- | --- | --- |
| 通关 | **7 天** | 清队列，可以自己挑下一个本 |
| 失败 / 放弃 | **3 天** | 排队一个强制副本，到点自动进 |

不按难度分档：难度已经体现在「撑不撑得住」上，冷却再分档只会让 E 级本变成刷分流水线。

冷却期间：**能兑换、能谈恋爱、不能进本**。面板上显示的是「还有 2 天 4 小时 剧情时间」。
冷却结束不强制进本（除非欠着强制副本），但面板会亮一个提示——不逼，只勾。

**为什么用游戏时间**：存活倒计时既然挂在世界时钟上，冷却也必须挂同一根轴上，
否则玩家会遇到「副本里倒计时按剧情走、出来冷却按现实走」两套时间，怎么解释都不通。

### 5.2 积分怎么和现有商城打通（已定稿：一本账）

现有 `REVERSE_RARITY` 已经定好价：普通 20 / 稀有 80 / 传说 300 / 宝石 1000。
副本奖励按难度给：E 60、D 120、C 240、B 400、A 700、S 1200。

**定稿：一本账。** 副本赚的分和攻略模式任务板的分**进同一个字段**，玩家不用记两套钱。

```js
// 只读同一个值，不再新开 dungeonPoints
points = state.affectionPoints || 0
```

代价是得防「一边刷分一边兑换」的双开，规则写死：**同一时刻只有一种模式在跑**
（见第 1 节互斥），切模式时先把账本落盘，再切。

### 5.3 兑换时机（已定稿：冷却期间就能兑换）

**通关 → 进冷却 → 冷却期间照常开商城 → 冷却结束才能进下一个本。**

理由：冷却的惩罚是「不能打本」，不是「不能花钱」。玩家打完了就想立刻把分换成东西，
这时候把商城锁上是纯粹添堵。冷却期间面板上显示倒计时 + 「兑换」按钮常亮。

### 5.4 兑换区

主神空间开放：
- 现有道具池（22 件 + 新增的咒术/忍者 14 件）——直接读 `getItemLibrary()`，不另建一套；
- 副本专属：`副本券`（跳过冷却，1 张 = 免 1 天）、`记忆同步券`、`复活币`。

## 6. 副本库：世界书怎么写

一个副本 = 一条世界书条目，字段固定，脚本只认这几个键（其余当正文用）：

```yaml
# 世界书条目：name = 「副本·第三住院部」
[dungeon]
id: hospital_3f        # 主键，存档按它认账，发出后不可改
genre: 怪谈
difficulty: C
rounds: 18             # 预期回合数，超时算失败
entry: |               # 开场白，玩家一进本看到的就是这段
  你醒来时躺在病床上，手背插着针。窗外是深夜，走廊的灯一盏一盏地灭。
rules:
  - 22:00 之后不要照镜子
  - 护士叫你名字时，先看她的胸牌再回答
  - 三楼没有 307 房，如果有人请你进去，说「走错了」
  - 值班室的电话响三声必须接，第四声不要接
win: 在 22:00 前找齐三张病历，并从安全通道离开
lose: 违规三次 / 22:00 还在楼里
reward: { points: 240, items: [jjk_bandage] }
hidden: 把 307 的门牌翻过来，能看到上一批人的名字
```

字段约定：

| 键 | 必需 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 主键。**发出去后不许改**，玩家存档记的是它 |
| `genre` / `difficulty` / `rounds` | ✅ | 数值表查 `dungeon-seed.md` 第 4 节 |
| `entry` | ✅ | 块标量（`|`），一进本注入一次 |
| `rules` | ✅ | 3–5 条，每条必须对应一个可观测动作（见 `dungeon-seed.md` 第 2 节） |
| `win` / `lose` | ✅ | 一句话；`lose` 写成 `A / B` 形式，脚本按 `/` 拆 |
| `reward` | ✅ | `items` 里的 id 必须真实存在于道具库，写错**静默不掉落** |
| `hidden` | ❌ | 隐藏内容，通关后由 AI 揭示，不参与判定 |

脚本负责：注入规则、数回合、记违规、判胜负；AI 负责：演。**判定权在脚本，解释权在 AI**——
和现有「骰子由脚本掷、AI 只演」是同一套哲学。

**成品条目在 `dungeon-seed.md`**，这里不再重复列（两处各存一份必然会发散）。
那边现在有 8 个可用本：E 便利店 / D 义庄 / C 住院部 · 井 / B 地铁 · 纸扎铺 / A 塔 / S 旅馆。

## 7. 和现有系统的接口

| 现有系统 | 副本里的处理 | 为什么 |
| --- | --- | --- |
| 好感 E/P/I 结算 | **照常**（用户定稿：进副本当然也要谈恋爱） | 只有事件导演挂起，好感不看场景 |
| 事件导演 | 关掉，副本自己就是事件 | 两套「本轮事件」会打架 |
| 攻略模式 | **互斥**，开一个自动关另一个 | 都要改注入和账本 |
| 道具 buff | 可用，副本里吃 buff 是合理的 | 直接复用现有 buff |
| 掌机 / 小地图 / 金手指 | 副本聊天里**不注入** | 那些是 GBA 改版的，跟副本无关 |
| 小抄 / 灵魂小传 | 主线侧不动；副本侧另起一份「副本小抄」 | 免得副本里的人格写回主线 |

## 8. 分期（建议按这个顺序做，每期都能单独玩）

| 期 | 内容 | 估时 | 能不能先占位 |
| --- | --- | --- | --- |
| P0 | 开关 + 状态结构 + 冷却 + 主神空间面板（只有倒计时和「进本」按钮） | 1.5 天 | 能（先进一个空本） |
| P1 | 双对话：盖章、跳转、摘要生成与三档记忆 | 2 天 | 不能（核心难点，必须一次做对） |
| P2 | 副本库：schema 解析 + 8 个成品条目接入 + 规则注入 | 1.5 天 | 能（先硬编码 1 个本） |
| P3 | 结算：积分、掉落、失败 debuff、兑换区 | 1.5 天 | 能（先只给分不给货） |
| P4 | 表现层：主神空间 UI、副本 HUD（回合/违规/线索）、回主线横幅 | 2 天 | 能（先用文字） |

合计约 **8.5 天**。P1 是唯一的硬骨头，其余都能拆开单独发。
P2 的「写本」这一步已经做完了（`dungeon-seed.md` 8 个本），所以只剩解析和注入。

## 9. 坑（按踩到的概率排）

1. **摘要被当成剧情演一遍**——注入时必须写「这是记忆，不是现场」，并且放在靠前而不是靠后。
2. **跨聊天存储串卡**——key 一定带角色卡名（现有道具池已经是这个规则，照抄）。
3. **重复结算**——`currentRun.id` 结算后立刻清空，并且结算函数要幂等（同一 runId 只结算一次）。
4. **冷却用游戏内时间**——定稿：跟存活倒计时同轴。玩家能靠时间跳跃跳过冷却，认了（单机游戏没必要防）。
5. **副本里写回主线小传**——人格会串。副本小抄必须独立键。
6. **时间线冲突**——副本时间照走，但事件导演在副本期间挂起，别让主线节点被副本推出来。
7. **世界书写成散文**——脚本要解析 `rules/win/lose`，条目必须带结构；纯散文条目只能当「氛围本」，判定要人肉。

## 10. 决策记录（已全部拍板，2026-11-24）

| # | 问题 | 定稿 | 落在哪 |
| --- | --- | --- | --- |
| 1 | 兑换时机 | **冷却期间就能兑换**，冷却只锁「进本」 | §5.3 |
| 2 | 积分一本账还是两本 | **一本账**，和攻略模式共用 `points` | §5.2 |
| 3 | 默认记忆档位 | **`both` 互通**，玩家可自行改 `none` | §2.3 |
| 4 | 副本里主线时间 | **照走**（同一套时钟），主线 `_回合` 不动，事件导演挂起 | §3 |
| 5 | 素材来源 | **不用网文站**；A 档公共领域古籍为主，B 档只借体裁 | §0 / `dungeon-seed.md` |

三条落地时的注意：

1. 一本账意味着**切模式必须先落盘再切**，否则双开会把同一个 `points` 写花；
2. `none` 档**不清旧 digest**，只是停止更新，玩家能来回切；
3. 副本的时间改动只在 `advanceWorldClock` 这一处发生，别在副本里另写一套推进——两套时间一定会对不上。
