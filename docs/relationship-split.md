# 关系系统：脚本管什么，世界书管什么

> v5.17.1 起的定调。改动集中在 `src/35-stat.js`（提示词）与 `src/50-calc.js`（成就闸门）。

## 一句话

**脚本只出「数值 + 关系名」，世界书出「这种关系怎么演」。**

| | 谁负责 | 落到 prompt 里的样子 |
| --- | --- | --- |
| 好感 / 亲密的加减 | 脚本 | 直接给数字，AI 不许改、不许复述 |
| 现在算什么关系 | 脚本 | `关系阶段=朋友 / R=2` |
| 朋友怎么相处、暧昧到什么程度、能不能告白 | **世界书 / 玩家设定** | 脚本只写一句「以世界书为准」，不写具体行为 |
| 关系判断本身 | 脚本 | 已判定完成，AI 不再自己评估 |

## 为什么这么切

玩家手里的感情向世界书，往往比脚本更懂「这个角色眼里的朋友是什么样」。
脚本如果也去规定表现（比如「高好感就该亲近」），两套说法就会打架：
AI 一边看到世界书写「她慢热」，一边看到脚本暗示「分数够高可以主动」，结果写出来人格分裂。

所以脚本退一步：只做**账本**，不做**导演**。

## 具体改了哪几句（`src/35-stat.js`）

### 每轮状态注入（`injectStatusPrompt`）

```
→ 脚本只负责两件事：好感/亲密的加减结果，以及它落在哪一档关系。
  它不负责「这一档关系该怎么表现」——朋友怎么相处、暧昧到什么程度、
  恋人间怎么说话，一律以世界书和玩家设定为准；世界书若对当前关系有定义，
  以世界书为准，本段不得与它竞争，也不要自己另立一套标准。

→ 关系判断已经完成，不要再自行评估或改写：不要写「我们算不算朋友」
  「关系好像进了一步」这类自评，不要用分数反推关系，也不要因为分高就
  自动加戏、因为分低就刻意冷场。需要提到关系时，直接用给定的阶段名。
```

### 关系事实注入（`injectRelationshipFactsPrompt`）

标题从「仅为事实背景」改成「**只声明关系，不规定表现**」，并加了两条：

- 剧本里谁更亲近、谁先低头、能开什么玩笑、要不要告白，按世界书和角色卡来写；**冲突时世界书优先**。
- 关系已判定完成，正文里不讨论「我们算什么关系」。

## 玩家的世界书该怎么写才接得上

不用改脚本，写清三件事就够：

1. **定义关系**：`朋友 = 会互相损、不会主动肢体接触、遇到事会先找对方` —— 这类「可观察的行为边界」最有效。
2. **别写数值**：不要在世界书里写「好感 50 以上就可以接吻」，那会和脚本的账本打架；要写就写「除非她主动，否则不接吻」这种条件。
3. **称呼与禁区**：谁可以叫昵称、哪些话题不能碰。脚本只管「有没有登记过专属称呼」，具体用不用由世界书决定。

## 成就为什么变少了（`src/50-calc.js`）

| | 以前 | 现在 |
| --- | --- | --- |
| 触发条件 | 只要是「重大事件」就给（1d20 ≥ 15，25%） | 重大事件要 **≥ 19**（10%） |
| 彩蛋 | 20 必给 | 不变 |
| 主线节点 | 给 | 不变 |
| 冷却 | 无 | **同一角色 60 回合内最多一枚** |

调参就两个常量，在 `50-calc.js` 结算函数开头：

```js
const ACHV_MIN_DICE = 19;        // 想多一点改 18，想更少改 20（等于只认彩蛋）
const ACHV_COOLDOWN_TURNS = 60;  // 回合数，按一局 100 回合算 ≈ 一局最多两枚
```

## 不要做的事

- 不要在提示词里再加「好感 X 以上就该 Y」的行为规则 —— 那是世界书的地盘。
- 不要把成就阈值调回 15 —— 那正是「一晚上拿三个」的来源。
- 改完跑 `node scripts/build.mjs` 再跑测试，`--check` 能确认产物和 `src/` 同步。
