## 0. 玩家看到的是什么

屏里左上角多一扇窗：一张纸，中间一个一闪一闪的白方块，纸上是你走过的地形。

- 一开始是**空的**——这是妈妈在开局塞鞋时顺手给的那张图，一张白纸。
- 走过的地方自己画出来；没去过的地方是黑的。
- 绿底「入」是你从哪儿进来的；橙底「出」是上一张图从哪儿出去的。
- 进新地图（森林、洞窟、楼梯下面、解谜层）自动翻到新的一页，旧页留着，标题写着第几页。
- 「地图」按钮开关，标题栏 `–` 收起，`↺` 换一张白纸重画。

**它不是游戏里的道具**。改版的道具表、名字表、发放脚本都在卡带里，脚本层塞不进去（见
`travel-items-design.md` 第 5 节）。所以这张图活在掌机这一层：剧情上它是妈妈给的，机制上它是掌机照着
画面画的。这一点在攻略「这台机器」册里对玩家说清楚了，不装作是游戏内功能。

## 1. 为什么不读内存拿坐标

最直接的做法是读 RAM 里玩家坐标（`gObjectEvents[0].currentCoords`）。实测这条路走不通：

1. **核心没有内存出口。** `44gba.wasm` 只导出 `emuLoadROM / emuRunFrame / emuAddCheat /
   emuGetSymbol / emuResetCpu / emuUpdateSavChangeFlag`，而 `emuGetSymbol(id)` 只认 1=ROM、
   2=存档区、3=帧缓冲、4=金手指文本，别的 id 一律返回 0（源码 `port-wasm/main.cpp` 可查）。
   GBA 的 256KB 工作内存是静态数组，躺在 wasm 线性内存里，没有指针可用。
2. **就算从堆里认出那块内存，标定也不可复用。** 存档块里的 `pos`、`location`（地图组/编号）
   偏移是编译期常量，随改版变：同一份代号 BPEE 的改版，地图扩容后结构会挪。每换一个改版都要重新
   标定一次，还要人肉把「橙华森林的地图编号」记进表里。
3. 结论：这条路做出来能跑一个改版，换一个就崩，且验证成本极高（要先玩到森林）。**不做。**

于是改成读画面。改版怎么做都不会影响画面里「玩家在正中、格子是 16px」这两件事。

## 2. 算法：把每一帧按格对齐拼起来

```
每 ~110ms 取一帧 240×160 RGBA
      │
      ├─ 这一帧是 UI 吗？（对话框 / 菜单 / 渐黑渐白 / 纯色）→ 是：跳过，不计失败
      │
      ├─ 还没有当前页 → 开一页新纸
      │
      ├─ 当前页刚开 → 冷却 16 次采样（约 1.8s），躲开「地名横幅」
      │
      ├─ 新纸上第一次 → 直接把整帧贴上（玩家格对齐纸中心）
      │
      └─ 否则：在上一格的 ±2 格范围里找最贴合的位置（像素差最小的那一格）
              ├─ 平均差 ≤ 12 → 对上了：贴上去（位置变了就是走了一步）
              ├─ 对不上但画面在动 → 走路/滑步中，正常，等它站定
              └─ 对不上且画面静止，连续 4 次 → 换地图了：给旧页标「出口」，翻新页
```

关键假设只有一条：**站住的时候，镜头刚好落在 16px 格线上，玩家在画面正中（第 7 列第 5 行）**。
GBA 的镜头是跟着玩家走的，走动时整屏滚动、停下时对齐格线，这条假设对绝大多数野外/迷宫地图成立
（屋子和一屏就装下的小房间不成立，见第 4 节）。

几个细节：

| 细节 | 做法 | 原因 |
| --- | --- | --- |
| 玩家立绘 | 贴图时挖掉画面正中 20×36 那块（`HOLE`） | 否则小人会被烙进地图，之后再也擦不掉；挖大了地图中间会留一块黑 |
| 底部条带 | 只拼到 y=124（`CLIP_Y1`），最下面 36px 不拼 | 这版改版在屏幕底部常驻一条 HUD（时间 / 背包 / 队伍），它钉在屏幕上不跟地图走，拼进去会糊成一片 |
| 自动翻开 | 要「真的走过一步」（`page.moves >= 1`）才弹窗 | 开场白、菜单那种静止画面不该把地图翻出来 |
| 匹配采样 | 每 4 像素取一个点，跳过挖洞区 | 1450 个采样点，25 个候选位置约 3.6 万次比较，9 次/秒无压力 |
| 图纸大小 | 44×44 格（704×704） | 一屏 15×10 格，留 ±14 格余量；单页约 2MB |
| 贴边 | 玩家进入边缘 8 格时整张图挪回中间 | 否则刚走的路会被顶出纸外 |
| 页数 | 最多留 3 页 | 一页 2MB，留多了吃手机内存；旧页的 `cv` 跟着丢掉 |
| 绘制 | 小窗画布固定 192×144（12×9 格，1:1 像素） | 与图纸像素 1:1，缩放时 `image-rendering:pixelated` 不糊 |

## 3. 判定阈值从哪来

| 判据 | 阈值 | 依据 |
| --- | --- | --- |
| 白底（菜单、渐白） | 白像素 > 30% | 野外画面白像素通常 < 5%，菜单/过场 > 60% |
| 黑场（渐黑、黑屏） | 暗像素 > 72% | 森林最暗的图块也不会到七成纯黑 |
| 对话框 | 底部 118px 以下同色 > 62% **且** 该色够亮（三通道和 > 480） | 对话框是整条浅色底；这条亮不亮的条件是给「底部常驻深色 HUD」留的——少了它，这版改版一张图都画不出来（实测 `box=1` 全被当成对话框） |
| 纯色 | 粗量化色数 < 8 | 过场、单色闪白 |
| 贴合 | 三通道平均差 ≤ 12 | 同一位置重贴是 0~2；错一格实测 60 以上 |

这些数字都在 `verify-map.mjs` 里对着合成帧钉住了，改阈值先跑测试。

真卡带上的实测（`probe-map-live.mjs`，改版 32MB 卡带，屋子里那一帧）：
`pale=0.004 dark=0.005 box=1 kinds=35 ui=false` —— 底部整条是深色 HUD，不该被当成对话框；
把这一帧平移 16px 再喂回去，状态机认出「往右走了一格」（`(15,17) → (16,17)`），
斜着挪 `(32,-16)` 认出 `(17,16)`，重新对齐后 1522 个采样点的像素差是 **0**。

## 4. 做不到的（对玩家也这么写）

1. **不是官方全图。** 没去过的地方是黑的，它不会凭空补出森林的全貌。当素描本用。
2. **小屋、单屏房间点位会偏。** 一屏装得下的地图镜头不跟人走，玩家不在正中，标记会偏一两格。
   地形仍然对（拼接是靠画面匹配的），只有「你」那个点会漂。
3. **画面被挡住时不画。** 对话框、菜单、渐黑期间一律跳过——宁可少画，不画错。
4. **会动的装饰会被抄进地图。** 水面波纹、花、走动 NPC 在拼接那一刻是什么样就留下什么样（再走一遍会被新画面盖掉）。
5. **换地图要等它反应。** 判定「换图」需要 4 次静止采样，约 0.5 秒；紧接着还有 1.8 秒冷却，所以进森林后
   大约 2 秒才会画出第一块；而且「翻开地图」要你在这张图上真的走过一步，站在原地看着是不会弹的。
6. **只留 3 页。** 走完第四张图，第一张就被丢了（只影响回看，不影响当前页）。

## 5. 以后要不要升级成真坐标

如果哪天满足下面任一条，可以换成读坐标，精度会从「格子级」变成「像素级」，小房间也不再漂：

- 换一个导出内存的核心（mGBA / libretro 的 WASM 构建有 `retro_get_memory_data`）；
- 或者给 44vba 加一个 `emuGetSymbol(5) → workRAM` 的补丁并重新编译（GPL-3.0，得一并提供源码）。

到那时代码只换 `MapCore.tracker` 的输入源即可，UI、图纸、标记、翻页逻辑都不用动——这也是把状态机
和绘制分开写的原因。
