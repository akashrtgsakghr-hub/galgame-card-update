# 全局美化包 · 制作文档（v2）

> 适用版本：5.3.1 及以后 · 主题格式 `moontheme/1`
>
> **这份文档不是风格样本，是施工规范 + 验收标准。**
> 风格来自你（玩家）最后写的那句话，不来自这份文档。
>
> 你（AI）的任务：把玩家脑子里的那个风格，翻译成一个能导入的 JSON。
> 文档里出现的每一个颜色、每一种材质、每一套示例，**都只是格式演示，一个都不要当成「标准答案」**。

---

## 0. 先把归属讲清楚

| 谁说了算 | 内容 |
| --- | --- |
| **玩家** | 冷还是暖、亮还是暗、素还是艳、要不要材质、可爱还是冷峻、复古还是未来、圆角大还是小、字距松还是紧 |
| **这份文档** | 字段怎么填、哪些值会让界面坏掉、哪些地方不能动、输出前怎么自查 |
| **插件** | 布局、节奏、动效、图标对齐、数字等宽——这些写死在代码里，主题碰不到 |

所以：**「我想要什么风格」这句话只有玩家能说，你不许替他默认。**
玩家没说，就问；玩家说得模糊，就按他的词选一个最贴的解，不要退回到「安全的中性暗色」。

### 0.1 反锚定条款（这条最容易被违反）

文档里给了示例配色，是为了让你看懂**格式**，不是为了让你照着配色。

- **不许**把示例里的色相、明度、材质当成默认值。
- **不许**因为「示例都是深色」就给玩家一套深色。
- 输出前自查一句：**如果我把这套皮和示例并排放，会不会像同一个设计师做的？**
  会 → 说明你在抄，回去照玩家的话重做。
- 玩家的描述如果和示例方向相反（比如「我要奶油白、要亮、要软」），
  **直接做相反方向**，不要折中成「微亮的深色」——那不叫稳妥，叫没听懂。

## 1. 从玩家的话，走到 token

这一步没有标准配方，只有**映射规则**。同一个人说「雨夜」，可以做出冷蓝、可以做墨绿、
可以做霓虹紫，都对。你要做的是：**挑一个最贴他其它描述的解，然后把它做扎实。**

### 1.1 五个坐标

| 坐标 | 玩家的说法大概长这样 | 落到哪 |
| --- | --- | --- |
| **明暗** | 暗 / 亮 / 灰扑扑 / 发光 / 像纸 | `l0~l3` 的方向与区间，`shadow` |
| **温度** | 冷 / 暖 / 中性 / 阴天 / 黄昏 | 色相 H 落在哪一段 |
| **饱和** | 素 / 干净 / 艳 / 荧光 / 高级灰 | 各色的 S |
| **材质** | 纸 / 布 / 石头 / 金属 / 玻璃 / 噪点 / 不要图 | `images` 与 `blend` |
| **年代气质** | 复古 / 现代 / 未来 / 手作 / 工业 | `radius`、`letter-spacing`、`shadow` 的软硬 |

### 1.2 明暗：两个方向都合法

```
深色皮：l0(最暗) → l1 → l2 → l3(最亮)      相邻差 1%~3%
浅色皮：l0(最亮) → l1 → l2 → l3(最暗)      相邻差 1%~3%
```

**没有「必须深色」这回事。** 插件是按暗色设计的，但浅色跑起来一样成立
（浅纸、奶白、冷白、近乎无彩的灰都实测过）。唯一要跟着变的是文字方向：

- 深色皮：字要浅（`fg` 明度 88%~96%）
- 浅色皮：字要深（`fg` 明度 8%~18%）

如果玩家要的是「中间调」（灰蓝、雾紫这类），四层就在 30%~55% 之间铺，
字用近白或近黑，但对比度要顶到 10:1 以上——中间调最容易糊。

### 1.3 温度：色相不要只用一种

「冷」不等于「全部蓝」，「暖」也不等于「全部橙」。同一个色相家族里挪 10°~20°，
四层之间带一点色相漂移（比如 l0 偏蓝紫、l3 偏青），暗部才不死。
这是**可选项**，不是义务。

### 1.4 饱和：不是越低越高级

低饱和（S 8%~18%）确实稳，但那是**一种**风格，不是标准。玩家说「荧光」「赛博」「糖果」，
就该给 S 60% 以上——只要把它用在小面积上，并且和底色的对比撑住。

真正会坏的不是高饱和，是**高饱和铺大面积**。所以：

- 底色：随便，只要四层分得开
- 强调色：高饱和可以，但面积 ≤ 5%（按钮、聚焦环、进度、选中态）
- 文字：别用高饱和，会晃

### 1.5 材质：不是「要不要」，是「什么手感」

- 玩家没提材质 → 就 `{}`，纯色皮。**别自己加。**
- 玩家说「纸」→ 找纸纹；说「绒」→ 找低对比的方向性纹理；说「金属」→ 找细密的拉丝
- 没有图也不要编，用 `builtin:` 里现成的那几张，或者干脆不加

素材怎么调透明度，看 §5.4。**图越有主体、越有明暗起伏，透明度就得越低。**

### 1.6 年代气质：圆角与字距是最省力的两个旋钮

- 复古 / 手作：`radius` 0~8，字距 `0.01em` 以上，`shadow` 硬一点（透明度高、扩散小）
- 现代 / 干净：`radius` 12~16，字距 0，`shadow` 软
- 未来 / 工业：`radius` 0~4，字距 `0.02em` 左右，强调色可以跳得远
- 可爱 / 软：`radius` 18~24，`shadow` 淡而大

这四个方向都不是规定，只是「玩家说了这个词，你可以往这边拨」。

## 2. 最高指令（不许违反）

作者定的 UI 铁律，**原文一字不改**：

```
ui布局严格执行：1.禁黑框与#000，靠1-3%微明度4层背景分层；2.输入框聚焦禁描边，加深双环阴影；3.暗色字重全降40；4.流式打字blur(6px)渐显，120ms且字间错开30ms；5.图标下移0.125em对齐；6.数字锁tabular-nums防抖；7.折叠用Grid 0fr→1fr；8.正文开text-wrap:pretty；9.拖拽弹簧1200/80零回弹，点赞380/18微弹；10.复制对勾2.5s自隐。
```

### 逐条落地：哪些归你管，哪些你别碰

| # | 条款 | 在这份主题里怎么落实 | 你（AI）要做的 |
| --- | --- | --- | --- |
| 1 | 禁黑框与 #000，靠 1-3% 微明度 4 层背景分层 | `l0/l1/l2/l3` 四层底色，相邻差 1%~3%（深色往上亮、浅色往下暗都行）；`line/line2` 是发丝线，不是边框色块 | 给全四层，别把 `l3` 写成 `l2` 的复读；**任何 token 都不要写 `#000000` / `rgba(0,0,0,x)`** |
| 2 | 输入框聚焦禁描边，加深双环阴影 | 脚本已接管：双环 = `accent` 一环 + `shadow` 一环 | 保证 `accent` 与 `l2` 对比 ≥ 3:1，环才看得见；**不要**在 `css` 里写 `outline` |
| 3 | 暗色字重全降 40 | 插件在暗色下把字重从 600/400 降到 360/300 | 别写 `font-weight`（白名单不收）；`font-family` 别挑 Black/Heavy/Ultra 这类字面 |
| 4 | 流式打字 blur(6px) 渐显，120ms 且字间错开 30ms | 插件行为 | **别碰**：白名单没有 `animation` / `transition` |
| 5 | 图标下移 0.125em 对齐 | 插件行为 | **别碰**：白名单没有 `margin` / `padding` / `transform` |
| 6 | 数字锁 tabular-nums 防抖 | 插件已锁 | 换字体时确认数字等宽，别选装饰体 |
| 7 | 折叠用 Grid 0fr→1fr | 插件行为 | **别碰** |
| 8 | 正文开 text-wrap: pretty | 插件已开 | `letter-spacing` 保持 0~0.02em；复古风可以到 0.04em，再往上字会散 |
| 9 | 拖拽弹簧 1200/80 零回弹，点赞 380/18 微弹 | 插件行为 | **别碰** |
| 10 | 复制对勾 2.5s 自隐 | 插件行为 | **别碰** |

一句话：**你能改「颜色、材质、圆角、字距、字体」；不能改「结构、节奏、动效」。**

## 3. 硬线、软线、不管你

分清这三类，你就知道哪些是「必须」，哪些是「建议」。

### 3.1 硬线（会被拦下来）

| 项 | 后果 |
| --- | --- |
| `format` 不是 `"moontheme/1"` | 整份拒收 |
| 素材是 http / 相对路径 | 那张图丢掉，并在结果里报错 |
| 单张图 > 320KB，或三张合计 > 900KB | 丢掉超的那张 |
| `css` 里出现 `@` / `url(` / 尖括号 / `expression` | 整段不收 |
| `css` 用了白名单外的属性 | 那条跳过（其余照收） |

### 3.2 软线（不会拒收，但会当场改你的色）

| 项 | 脚本动作 |
| --- | --- |
| 任何 token 写成纯黑 | **自动染成最底层色**（保留透明度） |
| 文字对 `l2` 对比不够 | **自动往反方向抬**，直到过线 |
| 四层明度方向来回翻 | 提醒一句，不拦 |
| 四层相邻差 > 5% | 提醒一句，不拦 |

**注意**：这两条自动修正会改你的设计。所以别「赌它会帮我修」——自己先算过，
改出来才是你想要的。反过来，如果你就是要一个很暗的近黑底，写 `#0A0809` 而不是 `#000000`。

### 3.3 不管你的

亮色、荧光、高饱和、低饱和、无材质、大圆角、直角、衬线字体、等宽字体、
跳色相强调、单色系、几乎无彩——**这些都在自由范围内，插件不做任何假设。**

## 4. 字段表

| 字段 | 类型 | 必填 | 范围 / 取值 | 说明 |
| --- | --- | --- | --- | --- |
| `format` | string | ✅ | 固定 `"moontheme/1"` | 写错直接拒收 |
| `name` | string | ✅ | ≤ 24 字 | 面板列表里显示的名字 |
| `author` | string | | ≤ 24 字 | 署名，可以留空 |
| `desc` | string | | ≤ 120 字 | 一句话说清这套皮的气质 |
| `tokens` | object | ✅ | 见 §4.1 | 颜色与圆角 |
| `images` | object | | 见 §5 | 素材，最多 3 个槽 |
| `css` | string | | 见 §6 | 额外声明，只作用于面板本体 |

### 4.1 `tokens`

| 键 | 语义 | 硬性要求 | 自由度 |
| --- | --- | --- | --- |
| `l0` | 最底层 | 不能是纯黑 | 明度随便（深色皮 4%~12%，浅色皮 88%~97%） |
| `l1` | 第二层（卡片衬底） | 与 `l0` 沿同一方向差 1%~3% | 可带色相漂移 |
| `l2` | 第三层（正文落在这一层） | 与 `l1` 同上 | 同上 |
| `l3` | 第四层（输入框、浮起元素） | 与 `l2` 同上 | 同上 |
| `fg` | 主文字 | 对比 `l2` ≥ 7:1（低于就被抬） | 上限约 15:1，再高会刺眼 |
| `fg2` | 次文字 | ≥ 4.5:1 才合法；**低于 7:1 会被自动抬到 7:1** | 4.5~7 之间会被改，想原样保留就自己提到 7 |
| `fg3` | 弱文字 / 占位符 | ≥ 3:1 才合法；**低于 5:1 会被抬到 5:1** | 同上 |
| `accent` | 强调色（按钮、聚焦环、进度） | 与 `l2` ≥ 3:1 | 色相随便跳，饱和随便高，面积 ≤ 5% |
| `accent2` | 强调高光（标题、hover） | 与 `l2` ≥ 4.5:1 | 通常比 `accent` 亮一档，或跳 20°~30° |
| `line` | 发丝线（分隔、输入框边） | 用 rgba，别用实色 | 透明度 8%~18%，用文字色或底色都行 |
| `line2` | 强发丝线（面板外框、hover 边） | 同上 | 22%~34% |
| `shadow` | 投影色 | 带色相，别用纯黑 | 用 `l0` 的 rgb 加 60%~85% 透明度 |
| `radius` | 圆角（px） | 0~24 | 边界外会被夹住 |

## 5. 素材（贴图）

### 5.1 格式

只收内联 data URL：

```
data:image/webp;base64,<...>
data:image/png;base64,<...>
data:image/jpeg;base64,<...>
```

**外链一律拒收**（`http://`、`https://`、`file://`、相对路径）。原因很实在：
酒馆里的脚本不该在你不知情的时候向第三方发请求。

### 5.2 三个槽

| 槽 | 铺在哪 | 适合什么 |
| --- | --- | --- |
| `panel` | 整个面板底 | 横向或均匀的纹理：纸、布、丝、噪点、拉丝、云 |
| `card` | 卡片内衬 | 可选，不给就用纯色层 |
| `bar` | 面板里的状态条 | 可选，通常给同一张图压得更暗 |

```json
"panel": {
  "src": "data:image/webp;base64,UklGR...",
  "opacity": 0.6,
  "blend": "soft-light",
  "size": "cover",
  "position": "center"
}
```

| 键 | 默认 | 取值 |
| --- | --- | --- |
| `opacity` | 0.55 | 0.05 ~ 1 |
| `blend` | `normal` | `normal` / `soft-light` / `overlay` / `screen` / `multiply` / `luminosity` |
| `size` | `cover` | `cover` / `contain` / `auto` / `100% 100%` |
| `position` | `center` | 任意 CSS background-position |

### 5.3 体积上限

- 单张：解码后 ≤ **320KB**
- 三张合计：≤ **900KB**

超了会被丢掉，并在导入结果里告诉你哪张超了。

### 5.4 透明度的经验值（按「图的起伏程度」分，不按材质种类）

| 图的特点 | `opacity` | `blend` |
| --- | --- | --- |
| 细密、低对比（纸纹、噪点、细布） | 0.5 ~ 0.7 | `soft-light` |
| 有明显明暗起伏（珠光、云、丝绸） | 0.3 ~ 0.5 | `soft-light` |
| 有主体、有细节（照片、插画） | 0.12 ~ 0.25 | `multiply` 或 `luminosity` |

规律只有一条：**图越抢眼，透明度越低。** 因为脚本会在图上盖一层由 `l1`/`l2` 组成的压暗层，
`opacity` 越高，压暗层越薄，字越吃力。

### 5.5 没有素材怎么办

**别编。** 没有图就写 `"images": {}`，只给颜色——一套配色对味的纯色皮，
比一张糊住字的图好看得多。

也可以引用插件自带的素材（玩家侧不需要额外下载）：

```
builtin:nacreNight   鲍鱼贝内壁（暗）
builtin:paperNight   压暗的丝缎横纹
builtin:nacreDay     珠光纸（浅）
builtin:paperDay     冷白丝缎（浅）
builtin:coverNight   双扇贝（暗）
builtin:coverDay     双扇贝（浅）
```

> `builtin:` 只在插件里有效。要发给别人，先导出一次，导出会把内置图换成真图。

### 5.6 面板的「机身」也会跟着换

除了底色，脚本还会换掉：卡片衬底、液晶屏外框、页签选中态、按钮悬停、输入框聚焦环、弹窗描边。
它们各自绑在 `l0~l3` / `accent` / `line2` 上，所以四层排对，整机就是一套，
不会出现「底换了、边框还是原来的色」。

## 6. `css` 字段（可选）

只能写**面板本体**的声明，会被塞进 `#moon-phase-panel { … }`。白名单：

```
border-radius  box-shadow  backdrop-filter  -webkit-backdrop-filter
background-blend-mode  letter-spacing  font-family  text-shadow
border-width  border-style  filter
```

出现 `@`、`url(`、尖括号、`expression`、`javascript:` 的，整段不收。

```json
"css": "backdrop-filter:blur(3px) saturate(1.05);letter-spacing:.01em"
```

**不要**在这里写 `color`、`background`、`font-weight`、`position`、`animation`——
这些位置脚本自己管，写了也不生效。

## 7. 输出前自检

1. `format` 是 `"moontheme/1"`。
2. `l0/l1/l2/l3` 四层都在，**沿同一方向**递进（深色往上亮 / 浅色往下暗），相邻差 1%~3%。
3. 没有任何 token 是 `#000000`、`#000`、`rgba(0,0,0,…)`、`black`。
4. `fg` 对 `l2` 在 7:1 ~ 15:1 之间；`fg2` ≥ 7:1；`fg3` ≥ 5:1
   （低于这两条会被脚本自动抬亮，你的设计会被改——想保持原样就先算够）。
5. `accent` 对 `l2` ≥ 3:1，且它只出现在小面积（别拿它当背景）。
6. `line` / `line2` 是带透明度的 rgba。
7. `shadow` 带色相（`l0` 的 rgb + 透明度），不是纯黑。
8. `radius` 在 0~24。
9. `images` 里如果有 `src`，是 `data:image/…;base64,` 或 `builtin:xxx`，没有 http。
10. 素材单张 ≤ 320KB、合计 ≤ 900KB。
11. `css` 只用了白名单属性。
12. 输出是**一个 JSON 对象**，没有前后解释，没有代码围栏。
13. **最后一条，也最重要**：这套皮的明暗、色相、材质，是从玩家的话里来的，
    不是从这份文档的示例里抄的。

## 8. 三套跨度示例（看格式，不要抄）

下面三套故意做得互不相似——一套浅、一套荧光、一套暖土。
它们存在的意义是证明**同一个 schema 能装下三个方向**，不是给你配色卡。

### 8.1 浅纸（亮色 · 低饱和 · 无材质）

```json
{
  "format": "moontheme/1",
  "name": "浅纸",
  "author": "示例",
  "desc": "米白纸面，砖红只做点",
  "tokens": {
    "l0": "#F8F4ED", "l1": "#F3EEE5", "l2": "#EDE7DC", "l3": "#E6DFD2",
    "fg": "#2B2521", "fg2": "#4E463E", "fg3": "#665D50",
    "accent": "#B85C3C", "accent2": "#D98D63",
    "line": "rgba(43,37,33,.13)", "line2": "rgba(43,37,33,.28)",
    "shadow": "rgba(120,104,88,.34)", "radius": 14
  },
  "images": {},
  "css": ""
}
```

### 8.2 荧光（暗色 · 高饱和 · 小圆角）

```json
{
  "format": "moontheme/1",
  "name": "荧光",
  "author": "示例",
  "desc": "近黑底，荧光青绿只用在线和点上",
  "tokens": {
    "l0": "#060A09", "l1": "#0A1010", "l2": "#0E1615", "l3": "#131E1C",
    "fg": "#D9FFF4", "fg2": "#8FE8D2", "fg3": "#5FBFAC",
    "accent": "#22F5B0", "accent2": "#7CFFD8",
    "line": "rgba(190,255,235,.14)", "line2": "rgba(190,255,235,.32)",
    "shadow": "rgba(0,20,16,.8)", "radius": 6
  },
  "images": {},
  "css": "letter-spacing:.02em"
}
```

## 9. AI 最容易犯的七个错

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| **抄文档示例的配色** | 第 100 套皮和第 1 套长得一样 | 从玩家的话里取，示例只当格式参考 |
| **没听懂就退回暗色** | 玩家要亮、要软，你给深灰，等于没做 | 玩家说了什么方向就做什么方向 |
| 四层写成同一个颜色 | 界面糊成一块，层级全没了 | 每层差 2% 明度 |
| 用纯黑当 `l0` | 会被自动染色，你的层次就变味了 | 深色用 `#0A0809` 这一档，别用 `#000` |
| 强调色铺大面积 | 廉价感，对比全乱 | 强调色只占 5% |
| 塞一张照片满铺 | 字全糊了 | `opacity` 降到 0.2 以下，或换 `multiply` |
| 输出带解释和围栏 | 导入框解析失败 | 只输出 JSON |

## 10. 导入

1. 打开插件面板 → **系统选项** → **外观与阅读**
2. 点 **主题包 / 导入**
3. 把 JSON 粘进输入框 → **导入并应用**（也可以点「选文件」直接选 `.json`）
4. 不满意：列表里点 **还原** 回出厂像素皮

导入时会当场验：纯黑会被染成最底层色、对比度不够会把字抬亮、四层方向不对会提醒。
**没出问题的话，界面不会告诉你任何事——那就是成功了。**

## 11. 给玩家的「风格输入单」

把下面这段填完，连同本文件一起丢给 AI。**填得越具体，出来的越像你想要的。**

```
我要做的风格：
1. 一句话感觉：<例：雨天的旧书店，暖黄台灯，纸有点发黄>
2. 明暗：<深色 / 亮色 / 中间调 / 说不清>
3. 温度与主色：<冷 / 暖 / 中性；如果有具体颜色就写>
4. 材质：<纸 / 布 / 金属 / 玻璃 / 噪点 / 不要图>
5. 一定有：<例：一定要有朱红印章那种一点红>
6. 一定不要：<例：不要粉、不要渐变、不要圆角>
7. 气质参考（可选）：<某部电影、某个游戏、某个年代的印刷品>
```

### 起手句（复制给 AI 用）

```
下面是一份界面美化包的制作文档。文档里的示例配色只是格式演示，请不要照抄——
风格完全按我下面的描述来，如果你觉得我的描述和文档示例方向不同，以我的描述为准。
只输出一个 JSON，不要解释。

<把上面那份「风格输入单」粘在这里>
```

**如果你只写了一句「我要 XX 风格」**：AI 应该先问你 1~2 个问题（明暗、材质），
而不是直接给一套深色灰紫。文档里没有任何一句话要求深色。
