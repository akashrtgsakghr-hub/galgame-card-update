# 瞬间移动：带一只念力系才走得了

掌机地图层工具条上的第三个按钮。选好目的地按一下，它把整段路替你走完（含跨图）。
本文写清三件事：**为什么不是「改坐标」**、**凭什么叫你有念力系**、**代跑怎么保证不跑飞**。

代码：`pocket/src/pocket.14-teleport.js`（读队伍 + 状态机）、`pocket/src/pocket.07-warp.css`（样式）。

---

## 一、为什么不是「嗖」一下真的传送

`44vba` 这个核心对外只导出四个内存符号：

| # | 内容 |
|---|---|
| 1 | ROM 缓冲 |
| 2 | 存档区（128KB Flash + 8KB） |
| 3 | 帧缓冲（240×160 RGBA） |
| 4 | 金手指文本缓冲 |

**没有「工作内存 / 玩家坐标」的出口，也没有写内存的接口。** 想真正改坐标只有两条路：

1. 改核心 C 源码重编译 wasm（GPL-3.0，能做，但那是另一个工程，且要重新验证整个模拟器）；
2. 打 ROM 补丁（往卡带里塞脚本），违背「卡带一个字节都不动」这条底线。

所以这里做的是**把路线按帧代按完**：一格 16 帧、换方向先转 8 帧，帧数喂得准，
实际跑起来比手按快一个量级，眼睛看着就是一串飞过去的画面。

> 代价说在前面：路上真有东西挡着（NPC、栅栏、遇敌），它会**停下**而不是穿过去。

### 为此给核心加的两个口子

| 接口 | 作用 |
|---|---|
| `GBA_CORE.step(n)` | 同步跑 n 帧、把最后一帧贴回屏幕 |
| `GBA_CORE.clock()` | 单调帧计数（`coreFrames` 每 500ms 清零，只能算 fps） |
| `GBA_CORE.manual(on)` | 代跑期间让 rAF 循环让位，避免两边同时喂帧 |

按帧而不是按毫秒，是因为倍速一开（金手指台那个 ×2/×4）毫秒就不准了，帧数是死的。

真机实测（官方 16MB 卡带，`probe-teleport-live.mjs`）：

```
静止 90 帧            → 画面变化 0 像素
按住方向键 90 帧      → 变化 10355 / 17290 / 38126 像素（左 / 上 / 右）
```

## 二、凭什么叫你有念力系

不弹窗问玩家，直接读卡带存档里的队伍。

### 数据结构（对着 `pokeemerald/include/global.h` 抄的，官方卡带逐条验过）

```
Flash 0x20000
├── 扇区 0         SaveBlock2
├── 扇区 1..4      SaveBlock1（每扇区前 0xF80 是数据，尾 0x80 是扇脚）
└── 扇脚 @0xFF4    u16 编号 · u16 校验 · u32 0x08012025 · u32 计数器

SaveBlock1
├── +0x000  pos（s16 x, s16 y）
├── +0x004  location（WarpData：组/编号/门/x/y）
├── +0x234  队伍数量（u8）
├── +0x238  队伍（6 × 100 字节）
└── +0x490  金钱
```

### 一只宝可梦 100 字节

* 头部 0x20 明文：性格（u32）、初训家 ID（u32）、名字、校验
* 数据段 0x30（12 个 u32）：**每字异或（性格 ^ ID）**，再按 `性格 % 24` 决定四段（成长/招式/努力/杂项）的排法
* 成长段：`[0]=物种|道具`、`[1]=经验`、`[2]=pp奖励|亲密度|未用`
* 招式段：`[0]=招式0|招式1`、`[1]=招式2|招式3`

判定就是「四个招式里有没有 100 号（`MOVE_TELEPORT`）」。
24 种排列全部单独测过，错一位就会解出乱七八糟的物种，测试会立刻发现。

### 为什么是「最后一次存档」

存档区是唯一能稳定拿到的真游戏状态。它是 Flash 的镜像——**游戏里不按保存，它就不更新**。

所以：

* 抓完凯西 → 游戏里 `START → 存档` → 回来点「重新验」，之后一直记着（缓存 2 秒，避免开图时反复解压）
* 没存过档就老实说「存档区还是空的」，不猜

三种「没解锁」分开说，不再一律弹同一句：

| 情况 | 面板怎么说 |
|---|---|
| 核心没在跑 | 先插一张卡带 |
| 存档区全 FF | 游戏里还没存过档，`START → 存档` 一次 |
| 读到了但对不上（改版动了结构） | 给一个「手动开锁」的后门 |
| 队伍里没这招 | 列出这次存档里的队伍，告诉你差什么 |

## 三、代跑怎么保证不跑飞

状态机（`tpStepOnce`）一次只做一件原子事，调度器用 rAF 反复调它：

```
① 按住一个方向走完一段（同方向连步合成一次长按）
② 一段走完 → 等 46 帧过场 → 重新认位置 → 重算路线
③ 最后一段走完 → 再认一次，对上了才说「到了」
```

三条防线：

| 防线 | 触发条件 | 结果 |
|---|---|---|
| 认不出就重试 | 跨完图 `navIdentify()` 返回空 | 最多 6 次，还不行就停（**绝不拿旧坐标接着按**） |
| 「8 圈」闸 | 重算路线超过 8 次 | 停，说明在打转（多半被 NPC 顶住） |
| 白屏检测 | 全屏 80% 以上是亮白 | 停 —— 战斗过场会整屏刷白，这时路线已经没意义 |

另外：

* 和「走过去」互斥（两套代按同时按方向键会打架），谁后点谁接管
* 关掉地图层、再点一次按钮、或按「清空」都会立刻松手（`tpEnd` 里把四个方向键全放开）
* 瞬移完会 `mapReset()`：一下跳出老远，旧的手绘地图册已经没意义了

## 四、它做不到的

* **不能穿墙**。它不是传送，是快速代走，所以要冲浪/潜水/秘传技的地方照样过不去（`moonPlan` 会直接说「走不过去」）。
* **起点必须认得出**。站在对话框/菜单/战斗里点它会说「这一帧认不出你在哪张图」。
* **进屋之后大概率认不出**（地板太素，识别宁可返回空也不乱指），这时候瞬移用不了。
* **遇敌会中断**。打完再点一次。
* **读的是最后一次存档的队伍**。刚抓的宝可梦，不存档就验不到。

## 五、测试

| 命令 | 覆盖 | 结果 |
|---|---|---|
| `node tools/verify-teleport.mjs` | 合成 Flash 存档、性格 24 种排列、三种失败原因、跨图代跑、堵死闸、白屏闸 | 22/22 |
| `node tools/probe-teleport-live.mjs` | 真卡带：按帧推进是否驱动游戏、写进带凯西的存档后能否解锁、界面文案 | 见输出 |

真机输出示例：

```
按帧推进：时钟走了 482 帧 · 静止 90 帧基线 0 像素
  按住各方向 90 帧的变化：down 0 · right 38126 · up 17290 · left 10535
写存档之前：锁着 · 存档区还是空的——游戏里还没存过档
写存档之后：解锁 · 凯西（第 2 只）
解析出的队伍：["263/Lv6","63/Lv11/瞬移"]
工具条按钮：「瞬间移动 · 凯西」 锁=false
```

> 注：测试里那份存档是**合成**的（脚本按上面第三节的结构造出来再写进 Flash 区），
> 用来验「解析 → 判定 → 界面」这条链。真实游玩时它来自玩家自己在游戏里存的档。
